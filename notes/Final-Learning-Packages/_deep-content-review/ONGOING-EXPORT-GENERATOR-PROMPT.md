# Ongoing Export Generator — Content-Quality Prompt

Copy and paste this prompt into any terminal generating or repairing a final learning package.

```text
Generate or regenerate the complete final package for:
<Subject> — <Section> — <Topic>

This is a content-first export, not a layout-only or file-presence task. Produce and validate all
four artifacts as one consistent package:

1. Complete Learning Session
2. Solved Practice Workbook
3. Carvaka-style Continuous Graphical Flowchart
4. ASCII Master Flowchart

SOURCE LEDGER
- Read the official syllabus, topic catalogue/manifest, complete Core Markdown owner, relevant
  cross-topic Core owners, Advanced owner, repository PYQ ledgers and local verified PYQ material.
- Search official/reliable online sources for missing PYQs and current/research anchors.
- For changing facts, record exact source, date, status, URL and access date.
- Do not fabricate or silently infer facts, quotations, dates, marks, word limits or PYQ wording.
- If canonical Markdown is materially wrong or incomplete, correct the source owner first and
  record the precise change; do not hide a source defect only inside generated output.

CORE / ADVANCED BOUNDARY
- Create a coverage ledger classified as CORE, PYQ-TRIGGERED CORE, SUPPORTING or OPTIONAL ADVANCED.
- Every official-syllabus concept, prerequisite mechanism, major distinction and verified PYQ
  demand must be taught in Core before:
  OPTIONAL ADVANCED DEPTH — NOT REQUIRED FOR A CORE ANSWER
- Advanced must be genuinely skippable enrichment. It must never repair missing Core teaching.

COMPLETE LEARNING SESSION
- Begin easily, then progress Foundation -> Core -> optional Advanced.
- Include goals, syllabus boundary, origin/timeline where relevant, precise definitions,
  plain-language explanation, visual-first teaching, mechanisms, comparisons, examples,
  objections/replies, exceptions, UPSC traps and a qualified conclusion.
- Add must-remember lines, evidence-based answer points, answer-grabbing opening/transition/
  conclusion lines and final consolidated register notes covering every subtopic.
- Qualify disputed interpretations and comparative heuristics. Do not flatten contested views
  into settled doctrine.
- Current affairs/research is an illustration unless it is authoritative doctrinal evidence.

SOLVED WORKBOOK
- Include every relevant verified PYQ with exact/qualified wording, year, paper/section, marks and
  word-limit guidance.
- For each answer include demand decoding, a detailed examiner-grade model, an executable
  exam-length version or compression plan, Why this earns marks, and specific How to improve this
  answer guidance.
- Add original 10-, 15- and 20-mark questions with model solutions.
- Add hard MCQs covering the complete topic and nearby traps using single-best-answer,
  statement-combination, matching and chronology formats.
- Rotate correct options strictly A -> B -> C -> D.
- Relabel only parsed option/answer fields. Never run letter replacement over explanatory prose.
- Verify every statement and ensure option relabelling preserves the correct option's text.

FLOWCHARTS
- Build both flows from the same complete source ledger.
- Each flow must independently reconstruct:
  central question -> conceptual axes -> complete Core -> mechanisms -> comparisons and
  objections -> consequences -> traps/PYQs -> answer spine -> qualified conclusion.
- Include exact technical terms, chronology/data, distinctions, limits and all major PYQ routes.
- Keep Advanced visibly subordinate. Do not compress away Core content.
- Ensure graphical and ASCII versions agree exactly with the session and workbook.

METADATA AND VALIDATION
- Create a new immutable generation; preserve previous reviewed generations.
- Derive generation number/date, source hashes, paths, page counts, previews, MCQ audit and
  validation metadata from the exact shipped files, never a previous generation.
- Reject truncated definitions, malformed Markdown, ellipsis placeholders, generic filler,
  repeated closure text, stale identity, missing files, empty pages, clipping and overlap.
- Compare prose before and after MCQ rotation to detect accidental mutation.
- Re-extract final MCQ keys and require strict A-B-C-D rotation.
- Run the existing targeted tests and all four-artifact validators.
- Do not mark the package export-ready if any material factual error, Core omission,
  fabricated/misattributed PYQ, weak model answer, stale audit or artifact contradiction remains.

Before finishing, output:
1. Exact source files changed and why.
2. New generation identity.
3. Four artifact paths.
4. Coverage/PYQ/current-source evidence summary.
5. Validation commands and results.
6. Any remaining uncertainty requiring human review.
```
