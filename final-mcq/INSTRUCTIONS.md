# Final MCQ revision bank: mandatory instructions

Read this file **before every generation, revision, audit, or export pass, and before starting or resuming each topic or current-affairs month**. Also read `AGENT_MEMORY.md` and the applicable repository instructions. Do not rely on a previous pass's memory of these rules. If a source or rule conflicts, resolve the conflict before publishing questions.

## Purpose and scope

- Build an extensive, exam-ready, **Prelims** question bank from all relevant syllabus topics and repository knowledge. Keep static subjects under `subjects/<Subject>/<Topic>/`, Vajiram monthly material under `current-affairs/<YYYY-MM>/`, optional-subject practice under `optional/`, and cumulative timed sets under `mixed-tests/`. Never mix current-affairs questions into a static bank without a source and dated cross-reference.
- Use the topic catalogue and the existing `upsc-ai-kit/practice/All-Topics-MCQ/` index to enumerate the full scope. The existing bank is a **coverage source**, not a finished final test: its workbook keys may be patterned and its options may be unbalanced. Include CSAT; distinguish GS-Prelims material from optional-subject and Mains-only material rather than silently dropping either. Essay and qualifying-language tasks are not four-option GS-Prelims topics; record them as explicitly out of scope.
- Work in catalogue order within each subject. Record every topic or month as `pending`, `in_progress`, `blocked`, or `complete`; never mark a partial bank complete. Preserve the existing practice atlas and source files.
- Give each topic its own folder and each subject a navigation index. Prepare **three different question sets in advance**, under `revision-1/`, `revision-2/`, and `revision-3/` inside *every* topic folder (and every CA month). These labels identify banks, **not learner attempts**: the learner will use them next year. Each set must independently cover the topic/month in depth, with new questions and different angles; do not simply reshuffle the same questions. Revision 1 establishes full coverage, Revision 2 revisits it with tougher cross-links and traps, and Revision 3 tests retention through application and mixed UPSC-style framing. Do not rely on future user attempts or guessed-answer data when authoring sets now.

## Required pre-pass checks

1. Re-read this file and `AGENT_MEMORY.md`; identify the exact next topic/month and previous progress. Read its Basic/canonical Markdown **completely**, then Advanced and relevant cross-topic knowledge and existing solved workbooks/PYQ records. Use OCR-searchable local PDFs for deeper or disputed details. For monthly CA, inspect the actual Vajiram *Recitals* PDF, confirm its month/year and page references, and deduplicate duplicate editions; use live official sources to check time-sensitive updates. Qdrant is optional and must not delay work.
2. Build a coverage ledger of every examinable subtopic, named example, important distinction, error pattern and verified PYQ. Do not skip an owner, section, month, question category or unresolved fact. Record gaps as gaps, not as implicit completion.
3. Draft original, genuinely distinct UPSC-style MCQs until the verified material is covered: conceptual application, multi-statement, matching, chronology, geography/maps, institution/power, elimination and close-option distinctions as appropriate. Maximise useful coverage, **not** the number of paraphrases. No arbitrary question cap and no compressed summaries in place of substantive tested coverage. Do not invent schemes, numbers, dates, attributions, source pages, questions or PYQ keys. Label original questions as original, never as PYQs.
   Include relevant **verified UPSC Prelims PYQs directly in the question sets**, explicitly labelled with year, paper, set and question reference. Check the wording against the local paper and map the answer to the matching official answer-key set before including it as a solved item. Preserve the original option order and official key for an exact PYQ; independent answer-position randomization applies to **original authored MCQs**. If a PYQ's choices are reordered, label it as *adapted from* the PYQ and recompute its key from the verified original. Keep its correct option and explanation only in that set's separate `ANSWERS.md`; cite both paper and key there. If the official key is unavailable or unreadable, record the PYQ as unresolved in `COVERAGE.md` rather than inventing a solution. Do not pad all three sets with duplicate copies of the same PYQ; original questions must still cover the complete topic independently.
   A published, UPSC-hosted scoring key qualifies as an official key even if its PDF does not literally print `FINAL`, provided it is not marked provisional or superseded. Record the upstream URL and confirm the local scan against that official file and the **same paper/series/question**; a locally named answer PDF or coaching key alone does not qualify. Keep a separate hold for unverified upstream provenance, dropped items, or reproduction rights (particularly full CSAT passages).
   UPSC's [website copyright policy](https://www.upsc.gov.in/website-policy) requires permission before reproducing its website material. Do **not** put an exact PYQ's protected wording/options in a new live bank unless the requisite permission is documented; keep its year/paper/series/question reference, authenticated answer-key evidence and conceptual coverage in `COVERAGE.md`, and test the concept with an independently authored question instead. Apply the same safeguard to previously drafted exact items while preserving a traceable hold. Verification of an answer does not itself grant reproduction rights.
4. Randomise each correct A/B/C/D position **independently** for final test delivery. Never rotate A-B-C-D or keep a predictable workbook/source-key sequence. Distractors must be plausible and independently checked; keep all four choices comparable in visible length, detail, specificity, grammatical form and formatting. Reject giveaway cues (a uniquely long or qualified answer, mismatched grammar, obvious absolutes, mutually exclusive clue patterns). For chronology questions, do not leak the order via dates in the options.
5. In **each** revision folder, put questions in an answer-free `QUESTIONS.md`; no key, solution, hints or revealing headings in that file. Put numbered correct answers, an explanation of **every option or statement**, sources and examiner traps in that set's separate `ANSWERS.md`. Record unresolved answers as blocked, not as guessed. For CA, cite magazine PDF and page plus any official update; separate ✅ sourced facts from ⚠️ analytical inferences.
6. Verify one-to-one question/key mapping, correctness, answer-position independence, option visual balance, distinctness between the three sets, topic/month coverage **in each set**, and absence of answer leakage. Record genuine gaps in the topic/month `COVERAGE.md` and indexes; update each set's status only after verification. Do not overwrite, delete, silently compress or declare completion of material that has not been audited.

## Sets for next year's revision

- Author, audit and save all three independent sets **before** declaring a topic/month bank ready; distinguish a `pending` set from a complete one. No score or attempt log is part of bank generation. If the learner later attempts a set, score +2 correct, -0.66 wrong, 0 skipped and report correct-but-guessed separately from confident correct answers.
- For time-sensitive Current Affairs, record the fact's source and as-of date. Before using a set next year, review developments, flag superseded facts and issue an explicit correction with sources rather than silently changing a previously released question.
- Corrections to any already attempted set must be explicit and versioned. Never claim that creating three empty folders completes three sets.

## Resume rule

On every subsequent pass, first open this file and the topic/month `COVERAGE.md`; resume from its first unchecked item and first unfinished set. If work stops mid-topic, leave all three sets' true statuses and remaining coverage visible. A partial question set is never represented as a finished topic.

For the active Medieval History queue, also follow `subjects/Medieval-History/PIPELINE.md` and run `python final-mcq/tools/medieval_pipeline.py` at the start and end of each continuation. The helper identifies the next queued topic and structural errors, **not** substantive release readiness. A scheduled run must save actual progress or a specific documented blocker rather than end at a status-only reply.
